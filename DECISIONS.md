## 2026-11-17: 60fps, near-lossless frames, research stats (C19), ElevenLabs
- Quality: Remotion's default frame capture is JPEG q80, which softened screenshots. Now `jpegQuality: 98`, x264 crf 15 with the `medium` preset, and 60fps output (`RENDER_FPS=30` to halve render time). Screencast frames are JPEG q100 and the recording uses crf 12. Clips are crf 16 at 60fps.
- Animations are written in 30fps "design frames" (`useDesignFrame`), so springs and fades keep the same speed at any output fps.

- Research statistics: the agent opens a reputable page that states the number (it has page fetch, no search) and returns url + quote. `src/lib/research/verify.ts` re-fetches the url (SSRF-checked on every redirect, HTML/text only, 3MB cap) and keeps the stat only if the exact value and unit appear in the page text, e.g. 64% matches "64%" or "64 percent" but never 164%. On failure, the stat, its source and every problem-scene sentence or text element that states an unbacked number are removed; an empty problem scene is dropped. `sources.md` lists every shown stat with the page excerpt we actually matched.
- TTS: ElevenLabs falls back to `ELEVENLABS_API_KEY`. The default voice changed from Rachel to Brian, because free-tier API keys can't use library voices (HTTP 402). Model is `eleven_multilingual_v2`.

## 2026-11-17: Brave search for problem statistics
- The agent's first reply includes `research_queries` and a problem scene with no stats. While the demo records, the server runs the queries on Brave (`src/lib/research/search.ts`), fetches the top 4 results per query (SSRF-guarded, no social sites or PDFs), and pulls out sentences that state a number. A follow-up turn in the same agent session (`previous_response_id`) picks at most 2. Only the problem scene and sources are merged back, so the recorded flow can't change. `verifyResearch` then re-checks each number on its page.
- Only the query text goes to Brave; there are no user identifiers.
- Cost: one more agent turn. No extra wall time as long as research finishes before recording does.
- Sentence splitting protects decimals (23.4%) and skips Title Case nav or headline soup.
- Source year: kept only if it appears within ~1500 chars of the matched number (news pages print the current year in sidebars); otherwise the citation omits the year (year = 0).

## 2026-11-17: Pacing (long pauses)
- The agent planned scene lengths at 2.5 words/s while ElevenLabs spoke at about 3.8, which left up to 5s of dead air per scene (silencedetect found 7 silences over 1.5s on tldraw).
- Scenes are now cut to their narration: lead 0.3s + voice + a 0.6s beat (demo) or 0.9s (titles). Floors are 2.6s for demo scenes (cursor move + click) and 3s for title scenes; the end card is 2.5s.
- ElevenLabs `speed: 0.85` gives about 3.0 words/s (measured). The agent is told about 3 words/s and that its words, not its durations, set the length.
- Result on tldraw: 62.4s, with only two gaps over 1.5s (about 1.7s each) plus the end card.

## 2026-11-18: Talking pace range, gap trimming, six style kits (C14a)
- Pace: `src/lib/pacing.ts` picks a base pace per video (0.88–1.25× natural, about 3 words/s) so the estimated length lands in 62–86s. A long script is read briskly and a short one more calmly. Sections vary around it: problem ×0.95, demo ×1.06. The pace goes per segment to the TTS (ElevenLabs speed = 0.85 × pace, clamped 0.7–1.2; OpenAI speed = pace).
- Gaps: each TTS clip has its leading and trailing silence trimmed (ffmpeg silenceremove at -45dB). Scene beats are 0.45s for demo and 0.7s for titles.
- Kits: midnight, paper, terminal, poster, aurora and clean. Each sets the backdrop, display font, weight and case, alignment, headline motion (fade-up, typewriter, slam), window chrome (mac-dark, mac-light, terminal, brutal, glass), caption style, label chip, accent bar, zoom ring and end-card CTA. The agent picks one by product type; "default" or an unknown id resolves by seed. The contract reports the kit actually rendered.
- Fonts are system stacks (Iowan/Palatino/Georgia for serif, SF Mono/Menlo for mono). Linux will fall back to DejaVu until fonts are bundled.

## 2026-11-18: Deploy on Railway (Hobby), not Netlify
- Netlify runs Next.js as short serverless functions: no 10-min jobs, no Chromium/ffmpeg, no persistent SQLite. Railway runs the Dockerfile as one long-lived container with a volume at /data.
- Railway trial (1 GB / 2 vCPU) could not render: memory sat at the 1 GB ceiling and Remotion timed out per frame, so jobs fell back to the plain editor. Hobby (8 GB / 8 vCPU) renders the full video: JSON Crack, 74.2s, 1080p60, 7/7 steps, 8:58 end to end.
- Container fixes: full node_modules in the image (tracing missed @rspack/binding), Remotion pre-bundled at build (REMOTION_BUNDLE), and caps because containers report the host's CPU count (RENDER_CONCURRENCY=4, FFMPEG_THREADS=4).
- Railway service vars: RECORD_SCALE=2, RENDER_SCALE=1.5, RENDER_FPS=60, MAX_CONCURRENT_JOBS=1, JOB_TIMEOUT_MS=2400000, RENDER_FRAME_TIMEOUT_MS=180000, STEP_TIMEOUT_MS=25000, OFFTHREAD_CACHE_MB=1024. Auto-deploy is off (Railway GitHub app not installed): deploy with "Deploy latest commit".

## 2026-11-18: Pitch upgrade: fonts, transitions, voices, judge pass, script review
- **Fonts are bundled** (@fontsource, OFL) into the Remotion bundle and the render waits on `document.fonts` before drawing frames. Why: the Railway container has no Inter/SF fonts, so videos fell back to DejaVu. Two new looks use them: studio (Instrument Serif, cinematic) and blueprint (Space Grotesk on a drafting grid). Eight looks now; a "default" plan's seed-based pick changed because the list grew.
- **Transitions are CSS only** (zoom-through, whip, push, plus Remotion's iris/flip), with spring easing and a fixed length so scene timing stays exact. Remotion's newer shader transitions need WebGL/html-in-canvas, which a headless server can't be trusted to have. Section boundaries are chosen by the renderer (zoom → solution, push → demo, iris → end) unless the agent names a newer one, because the agent mostly picked slide/wipe.
- **Voices**: 10 premade ElevenLabs voices that the account can use (checked with GET /v1/voices), each mapped to an OpenAI voice. "Auto" picks by look; a team's pick overrides TTS_VOICE, and on Auto TTS_VOICE still applies.
- **Judge pass**: one follow-up turn in the same agent session rewrites the *words only* as a judge would want them. The server merges only narration and headline/text/bullet strings by scene id, and keeps the rewrite only if the rule-based pitch check (8 checks: hook, specific problem, product named, ≥3 demo steps, payoff line, 60–90s, no hype, short sentences) scores at least as well. Stats are still verified after it, so it can't add numbers. Mock/offline planner runs skip it.
- **Script review (opt-in)**: the job pauses after recording with status `review`; the team edits narration and continues, or after 10 min it continues on its own. The job timeout pauses during review. The job link is the capability (same as revise). A paused job holds its render slot (MAX_CONCURRENT_JOBS=1), so the 10-minute cap bounds queue delay. After a restart, a job in review is marked failed, like a running one.
- **Public log** no longer shows HarnessRouter response ids or memory ids; tool calls are turned into plain lines ("Agent opened https://…").
- **Poster** is a caption-free Remotion still of the opening scene (needs its own `selectComposition`, because renderStill renders the props that selection resolved). The two landing-page samples keep their old posters: their source plans aren't on disk and they have captions from the first frame.
